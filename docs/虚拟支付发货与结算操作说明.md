# 虚拟支付发货与结算操作说明

## 先判断当前看到的是哪类订单

微信公众平台进入「虚拟支付 → 交易订单」后，先看左侧环境筛选：

- **沙箱环境**：只用于开发/体验版测试，不产生真实可提现资金。沙箱订单即使显示“待结算”，也不能提现吗。
- **正式环境**：正式版小程序用户实际支付的订单，才会进入真实分账和提现。

微信官方规则：一笔正式订单完成发货后，资金先冻结，按 **T+3** 分账；分账后才进入可提现余额。若是 Apple 支付，结算周期由 Apple 决定，通常为自然月结束后 45～60 天，再由腾讯划转。

## 本次补齐的代码

`payService` 现在同时使用两条发货确认链路：

1. 接收微信的 `xpay_goods_deliver_notify` 发货推送，发放权益并返回成功。
2. 小程序收到支付成功后调用云函数；云函数先调用微信官方 `/xpay/query_order` 查单。只有微信返回状态 2（已支付待发货）、3（发货中）或 4（已发货）时才发放权益，然后调用 `/xpay/notify_provide_goods` 主动确认已发货。

第二条是第一条失败时的官方兜底方式。代码不会只凭客户端结果发放权益。查单确认已支付后，权益与平台发货被拆成两个步骤：即使平台发货接口临时失败，用户权益也会先正常开通，后台发货状态会在后续打开页面时继续重试。

旧版本遗留的 `pending`、`paid`、未补报发货的 `delivered` 订单，以及因重新支付而关闭但从未查过微信状态的订单，会在用户再次打开会读取购买信息的页面时自动查单修复，每次最多处理 5 笔，避免单次执行超时。

## 必须部署的内容

在微信开发者工具里完成：

1. 找到 `cloudfunctions/payService`。
2. 右键 `payService`，选择「上传并部署：云端安装依赖」。
3. 等待部署成功，打开云开发控制台的云函数列表，确认 `payService` 的更新时间已经变化。
4. 确认该云函数仍有这些环境变量：
   - `XPAY_OFFER_ID`
   - `XPAY_APP_SECRET`
   - `XPAY_SANDBOX_APP_KEY`
   - `XPAY_PROD_APP_KEY`
5. 重新上传小程序代码并提交审核/发布。开发版、体验版固定走沙箱；只有发布后的正式版走正式环境。

> 不要把 AppSecret、AppKey 填到小程序前端。它们只应保存在云函数环境变量中。

## 微信公众平台后台检查

登录微信公众平台，选择当前小程序：

1. 进入「虚拟支付 → 基础配置 → 基础配置」。
2. 核对 AppID、OfferID 与云函数中的配置属于同一个小程序、同一个虚拟支付账户。
3. 核对沙箱 AppKey 和现网 AppKey 没填反。
4. 如果点击相关入口后进入的是需要填写 URL、Token、EncodingAESKey 的「消息推送配置」，先不要开通，也不要把普通云函数名称或云环境地址填进去。这个页面要求一个能完成微信 Token 校验、解密消息并按指定格式应答的公网 HTTPS 服务；当前 `payService` 不是这种 HTTP 回调地址。
5. `payService` 的部署在微信开发者工具中完成：在项目文件树找到 `cloudfunctions/payService`，右键选择「上传并部署：云端安装依赖」。也可以从「云服务 → 云开发 → 管理环境」进入云开发控制台，在「云函数」列表确认 `payService` 已经存在以及更新时间是否正确。
6. 本次新增的主动发货接口不依赖公众平台的「消息推送配置」。部署云函数后，支付成功时会由 `payService` 主动调用微信的 `notify_provide_goods` 接口完成发货确认。只有以后专门开发了微信消息 HTTP 回调服务时，才需要开通这页作为第二条通知链路。
7. 进入「虚拟支付 → 道具管理」，确认正式商品已经“发布至现网”，并且道具 ID、价格与代码一致：
   - 会员：`hot_topics_life`，99 元（9900 分）
   - 专题包：`topic_01`～`topic_13`，9.9 元（990 分）

## 修复已有“待结算”订单

### 沙箱订单

不需要处理提现。部署云函数和开发版后，让对应测试用户重新打开「我的」或购买页，旧订单会自动补发货；后台“发货时间”通常会在稍后更新，但它仍不会变成真实可提现余额。

### 正式订单

1. 先部署新的 `payService`。
2. 让购买用户重新打开正式版小程序的「我的」或购买页，触发自动补报。
3. 在云开发控制台查看 `payService` 日志；搜索：
   - `repair platform delivery failed`
   - `微信发货确认失败`
4. 回到「虚拟支付 → 交易订单」，把筛选切换为「正式环境」，重新查询该订单。
5. 确认“发货时间”已出现。已发货不等于立即可提现，之后还要等待 T+3 分账。

如果用户无法重新打开小程序，可在微信公众平台的订单详情中查看是否提供“确认发货/补发货”操作；有则可逐单处理。若页面无此按钮，需要由购买用户触发新代码，或通过服务端按订单号调用官方 `notify_provide_goods` 接口。

## 验收方法

先用开发版完成一笔沙箱支付：

1. 用户权益立即开通。
2. 微信后台该沙箱订单出现“发货时间”。
3. 云数据库 `communication_membership_orders` 对应文档中应出现：
   - `status: "delivered"`
   - `platformOrderStatus: 2/3/4`
   - `paymentConfirmedBy: "query_order"`
   - `platformDeliveryConfirmedAt`
   - `platformDeliveryError: ""`

再发布正式版并用最低价商品做一笔真实测试：

1. 在「正式环境」查询到订单。
2. 订单有发货时间，不再长期停留为未发货状态。
3. 等待 T+3 后，在「虚拟支付 → 资金管理」查看可提现余额。
